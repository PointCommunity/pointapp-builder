Design model · immutable where it matters

Authority, content, and release state.

Mutable collaboration records point to immutable content and release records. Database checks and transactional batches protect transitions; the browser never assigns authority.

Identity and access

Membership

github_user_id stable unique key; login, display name, avatar; role; status; requested/approved/disabled timestamps; approver; version.

Role: Editor, Publisher, Administrator, Owner
Status: Pending, Active, Disabled

Invariant: at least one Active Owner after bootstrap. New non-bootstrap identities are Pending Editors.

AuditEvent

Append-only event ID, time, request ID, actor identity/role/status snapshot, action, target type/ID, outcome, bounded reason, safe metadata JSON.

Denied and failed mutations are recorded alongside successful state changes. Secret values, OAuth tokens, raw bodies, and private keys are forbidden.

IdempotencyRecord

Actor ID + operation + key unique tuple, normalized request hash, status, safe response body/status, expiry, created/completed timestamps.

Reuse with a different request hash is a conflict. In-progress duplicates do not execute twice.

Authoring

Draft

ID, normalized name, state Active/Archived, current revision ID, created/updated/archive actors and timestamps, optimistic version.

Archive is reversible. Delete is not part of the user flow.

ManifestRevision

Immutable ID, draft ID, parent ID, monotonic sequence, canonical manifest JSON, SHA-256 checksum, schema version, label, actor, created time.

Save requires expectedParentRevisionId. A mismatch returns 409 and the current safe revision descriptor.

Manifest structure

Identity, theme, settings, screens, elements, navigation, audiences, campaigns, and referenced media IDs.

Object IDs are stable bounded identifiers. Ordered lists carry explicit order. External URLs are HTTPS and policy checked. No executable script or member PII is allowed.

Media

MediaAsset

ID, kind Image/Audio/Video, lifecycle Ready/Archived, filename/title, MIME, byte size, dimensions/duration, alt text or transcript/caption metadata, SHA-256, external HTTPS URL when applicable, creator/time.

MediaChunk

Image asset ID + zero-based chunk index unique key, binary payload, byte length. Chunks are written transactionally with asset metadata and reconstructed in order.

Visibility

Authenticated active members may fetch draft assets. Anonymous users may fetch only assets transitively referenced by the active Production manifest. Archived or orphaned assets remain private.

Release model

ReleaseEnvelope

Immutable ID, source revision, manifest digest, canonical manifest bytes, validation result digest, signing algorithm Ed25519, key ID, signature, publisher, created time.

The same envelope can be referenced by different channel events; channel is not part of the manifest bytes.

ChannelEvent

Append-only event ID, channel Staging/Production, release ID, kind Publish/Promote/Rollback, actor, reason, prior event ID, created time.

ChannelPointer

Exactly one row per channel with current event/release ID and monotonic version. Updated in the same batch that appends its event and audit record.

Production promotion must reference the current Staging release. Rollback must reference a prior Production release.

Database constraints

  • Foreign keys enabled; immutable tables expose no update/delete application path.
  • Unique constraints cover GitHub identity, draft revision sequence, media checksum where appropriate, channel name, request ID, and idempotency tuple.
  • Role/status/channel/kind values use CHECK constraints.
  • Lengths, counts, JSON schema, URLs, MIME, checksums, and accessible metadata are validated in TypeScript before prepared statements; critical state enums are duplicated as database checks.
  • Backward-compatible migrations only: create or add nullable/defaulted fields first, backfill explicitly, and rehearse against a baseline snapshot.
