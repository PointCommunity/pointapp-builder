Implementation Plan

This plan establishes governance without deploying the Builder or changing PointApp content.

Dependency order

  1. Read current PointSite Builder, PointApp Builder, GitHub, Project, PR, label, CI, and runtime configuration.
  2. Copy PointSite Builder Project structure without cards; rename, describe, link, and replace Canary-specific status text.
  3. Create the PointApp-aligned governed label taxonomy and read it back.
  4. Write AGENTS, the shared policy, eight workflow skills, five pinned shared skills, and cross-agent imports/adapters.
  5. Add test-first deterministic pipeline and live-verification contracts, including the exact PR #7 through PR #10 bootstrap exceptions.
  6. Wire package commands, CODEOWNERS, Dependabot, pre-commit secret scanning, and multi-job GitHub Quality.
  7. Run validators, focused tests, formatting, types, lint, contracts, migrations, coverage, security, build, performance, browser tests, and the live read-only audit.
  8. Review the final diff, commit only bootstrap files, push the current pre-pipeline branch, and require exact-head GitHub Quality.

Risks and controls

Risk Control
Native PointApp Project or repository is accidentally reused Create separate Project #5 and link only PointCommunity/pointapp-builder.
Copied Canary vocabulary misstates direct production Replace the In Review description and make the audit reject drift.
Builder deployment changes content channels Keep application and content release planes explicit in AGENTS, policy, skills, and verification.
Existing PRs #7 through #10 violate the new Issue invariant Recognize only their exact numbers, branches, and base as temporary audited exceptions.
Secrets or supply-chain flaws enter the bootstrap Use Gitleaks, TruffleHog, Semgrep, npm audit, pinned actions, and existing bundle/source scans.
GitHub branch protection is unavailable Report the plan limitation and enforce exact-tree/Quality gates with repository scripts.

Verification checkpoints

  • Project #5 readback matches the exact schema, descriptions, views, workflows, repository link, and zero-card state.
  • All governed labels match controlled names and colors.
  • All eight pipeline skills, five shared skills, 13 adapters, and imports validate.
  • Focused pipeline tests pass before full repository verification.
  • The final pipeline-health audit has no errors and reports only known warnings.
  • The final GitHub Quality run succeeds for the exact pushed head.
