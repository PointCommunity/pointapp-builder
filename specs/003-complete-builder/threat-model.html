Repository-grounded threat model · pre-implementation

Protect authority and the content supply chain.

Scope: the React Builder, Cloudflare Worker API, D1 records, GitHub OAuth integration, signed PointApp content channels, and public Production media. The separate native PointApp and app-store delivery are outside this repository.

Validation status

Owner question asked: should access requests accept any valid GitHub user or require PointCommunity organization membership?

Unconfirmed assumption: any valid GitHub identity may register as a Pending Editor. Pending accounts receive no protected data or mutation capabilities. If the Owner chooses organization-members-only registration, the OAuth/app permission and authorization design must be revised before deployment.

Trust boundaries

Untrusted browser ── HTTPS ──▶ Cloudflare edge / Worker │ │ │ GitHub redirect ├── protected API ──▶ D1 ▼ ├── secret bindings ─▶ OAuth + Ed25519 keys GitHub OAuth ◀───────────────────────┘ Anonymous PointApp client ── HTTPS + ETag ──▶ public Production channel / key / reachable media Boundary rule: static client assets contain no credentials, roles, drafts, private media, release authority, or signing secrets.

Assets and attacker capabilities

Critical assets

  • Owner/Admin authority and membership state
  • OAuth client secret and session-signing secret
  • Ed25519 private release key
  • Private drafts and non-production media
  • Immutable revision and release history
  • Production channel pointer and audit evidence

Credible attackers

  • Unauthenticated internet client
  • Pending or Disabled GitHub identity
  • Malicious/compromised Editor or Publisher
  • Compromised browser/session
  • Replay client or automated abuse source
  • Accidental operator or faulty deployment

Explicit non-capabilities

  • No assumed Cloudflare/GitHub administrative compromise
  • No native-app executable update through manifests
  • No direct access to the private repository
  • No server trust in client-displayed roles or hidden buttons

Security invariants

  • Only login start, OAuth callback, health, static assets, active Production content/key, and Production-reachable media are anonymous.
  • Authentication proves GitHub identity; D1 membership grants Builder authority. They are not interchangeable.
  • Every successful, denied, or failed high-value mutation has one correlated audit event.
  • The private signing key, OAuth secret, and session secret are Worker bindings and never response fields.
  • Local identity fixtures fail closed outside loopback development.
  • Changing the registration boundary or GitHub App permissions requires this threat model to be revisited.

Residual risks and operations

GitHub/Cloudflare control planes

Administrative compromise is outside application controls. Mitigate operationally with least privilege, organization 2FA, protected accounts, secret rotation, and audit review.

Immediate delivery

Online apps can observe a changed ETag immediately; offline devices cannot. The native app must verify signatures and atomically retain last-known-good content.

Human content risk

Schema validation cannot determine theological accuracy, image rights, or pastoral appropriateness. Human Staging review remains required before Production promotion.
